Por que trocar sua infraestrutura por uma pasta

Seis fichas, seis motivos — cada uma resolve um problema real de quem só queria persistir dados sem montar infraestrutura.

FICHA A

Zero dependências

Usa só fs, crypto e path — módulos nativos do Node. Nada pra instalar, nada pra quebrar numa atualização de terceiros.

FICHA B

Escrita atômica

Toda gravação vai pra um arquivo temporário e só então é renomeada. Uma queda de energia no meio da escrita não corrompe seus dados.

FICHA C

Índices reais

Campos únicos viram um Map em memória. Buscar por e-mail é O(1) — não uma varredura em todos os documentos da coleção.

FICHA D

Schema + validação

Tipos, campos obrigatórios, valores únicos, min/max, enum e formato de e-mail — sem precisar de mais uma biblioteca.

FICHA E

Transações com rollback

Agrupe operações em várias coleções. Se uma falhar no meio, tudo volta ao estado anterior — nenhuma escrita pela metade.

FICHA F

CLI + biblioteca

Prototipe pelo terminal ou importe com require() direto no seu backend. Os dois falam com o mesmo banco.

Linha de comando

Comandos que você vai usar todo dia

Sem configuração, sem servidor pra subir antes. É instalar e rodar.

bash — gbit-db-dados
# cria um banco de dados novo
$gbit-db-dados init ./meu-banco
 
# cria uma coleção e insere um documento
$gbit-db-dados create-collection users
$gbit-db-dados insert users '{"email":"a@a.com","name":"Ana"}'
 
# consulta com filtro em JSON
$gbit-db-dados find users '{"name":"Ana"}'
 
# estatísticas do banco inteiro
$gbit-db-dados stats
Como biblioteca

Também é só código

Um require() e o banco está pronto — sem client de conexão, sem pool, sem string de conexão pra guardar em segredo.

Um schema, uma coleção

Defina tipos e regras direto na criação da coleção. Campos unique já viram índice automaticamente.

  • → insert(), findById(), find()
  • → updateById(), deleteById()
  • → findByIndex() — lookup O(1)
  • → db.transact(() => {`{...}`})
const gbit = require('gbit-db-dados');

const db = gbit.open('./meu-banco');

const users = db.collection('users', {
  name:  { type: 'string', required: true },
  email: { type: 'string', required: true,
           unique: true, format: 'email' },
});

// grava com validação + índice automático
const user = users.insert({
  name: 'Ana',
  email: 'ana@ex.com',
});

// busca O(1) pelo índice único
users.findByIndex('email', 'ana@ex.com');

// tudo ou nada entre coleções
db.transact(() => {
  users.insert({ name: 'Bia', email: 'bia@ex.com' });
});

Onde seus dados realmente ficam

Tudo em JSON legível, dentro do seu próprio projeto. Pode abrir, ler e até editar na mão se precisar.

meu-banco/
├── database.json # metadados do banco
├── metadata.json # schema + índices de cada coleção
├── collections/
│ ├── users.json # documentos da coleção "users"
│ └── orders.json
├── indexes/
├── transactions/ # log de commits e rollbacks
└── backups/ # snapshots gerados por "backup"
